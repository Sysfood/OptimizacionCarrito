**No aplica.** `Producto` y `Existencia` no tienen diagrama de estado; EST-01 (Pedido) y EST-02 (Reserva) no intervienen en esta historia. La disponibilidad es un valor derivado, no un estado.

## Flujo de interacción
1. El estudiante abre el catálogo.
2. El sistema obtiene de la jornada vigente los productos con su nombre, precio, unidades vendibles y `fechaHoraActualizacion`.
3. El sistema muestra cada producto; si las unidades vendibles son 0, lo marca **Agotado** y no ofrece acción para agregarlo a un pedido.
4. El sistema indica la fecha y hora de la última actualización de la disponibilidad.
5. Si la fuente de inventario no responde o sus datos no son verificables, el sistema muestra **«Disponibilidad no verificable»** y no permite iniciar un pago con esa información.
6. Al cambiar el inventario, el catálogo lo refleja: la vista se refresca automáticamente cada 5 segundos (meta propuesta) y cada consulta lee el estado vigente.

**Variantes:**
- Producto sin unidades vendibles → se muestra agotado y no puede incorporarse a un pedido.
- Fuente de inventario no disponible o datos no verificables → aviso y bloqueo del inicio de pago.
- Cambio de inventario → el catálogo muestra las nuevas unidades vendibles en ≤5 s (meta propuesta).

## Decisiones tomadas en la validación
- **Fecha y hora de actualización (C5):** se agregó `fechaHoraActualizacion` a `Existencia` (opción A elegida por el estudiante). Documentos actualizados: `08-modelo-dominio.md` y `diagramas/modelo-dominio.puml`.
- **Fuente de inventario:** se implementa como interfaz simulada, con interruptor de demostración para el escenario «no verificable», porque la integración real con el software de ventas no está acordada (Derivación 3).
- **Venta del escenario CA4:** la venta pertenece a HU-03/HU-04. Para probar esta historia, el cambio de inventario se simula directamente en la base de datos; la interfaz de HU-01 no vende.
- **Acción de agregar al pedido:** el carrito es HU-02. En HU-01, un producto agotado se muestra como agotado y sin acción de agregar.
- **Meta ≤5 s (RP-14):** se implementa como refresco automático de la vista cada 5 s; no se promete un SLA de integración real.
